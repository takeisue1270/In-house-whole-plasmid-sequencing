# Whole Plasmid Sequencing（プラスミド全長シークエンス）

*[English README](README.md)*

Oxford Nanopore Technologies（ONT）のプラスミド用プロトコルと、Flye による
バーコードごとの de novo アセンブリをつないだワークフローです。研究用です。

> [!IMPORTANT]
> 本リポジトリで「in-house の変更」と明記した箇所を除き、ONT の文書が優先します。
> 変更箇所は次の 4 つです。バーコーディングの少量化、プール後の AMPure XP 精製の
> 省略、0.3 µL RA + 2.7 µL ADB によるアダプター付加、および PromethION 用の最終
> ライブラリ組成です。実行前に ONT の最新のプロトコルを確認してください。
> 次のいずれかに該当する場合は、製品付属の完全な手順を使用してください。ONT の
> 手順に厳密に従う必要がある場合、入力量の保証が必要な場合、ライブラリの回収量を
> 最大にする場合です。

## 対象の範囲

本ワークフローは、精製済みのプラスミド DNA から始まります。DNA 抽出の手順と
抽出キットの指定は含みません。研究室ごとに検証済みの方法が異なるためです。

本リポジトリが扱うのは次の 4 つです。

1. 少量化したバーコーディングと、精製を省略したアダプター付加
2. フローセルのプライミング、ロード、ランの設定、洗浄と保管
3. デマルチプレックス済み FASTQ の準備
4. バーコードごとの Flye によるアセンブリ

ロードの手順は 2 系統あります。MinION/GridION（FLO-MIN114）については ONT の
プロトコルに従います。PromethION（FLO-PRO114M）については in-house の試験的な
手順です。現行の ONT のプラスミド用プロトコルは、SQK-RBK114 の PromethION 用の
最終ライブラリ組成を定めていません。そのため PromethION の数値には各施設での
検証が必要です。この数値を ONT のキット準拠のプロトコルとして記載することは
できません。

実験手順は [PROTOCOL.md](PROTOCOL.md) と
[Whole_Plasmid_Sequencing_Protocol.docx](Whole_Plasmid_Sequencing_Protocol.docx)
にあります。いずれも英語です。ONT の手順からの変更点と、各施設で検証すべき事項は
[DEVIATIONS.md](DEVIATIONS.md) にあります。

## Sanger シークエンスとの使い分け

本ワークフローが適するのは、次の 3 つの場合です。複数のコンストラクトを全長で
確認する場合、繰り返し配列や想定外のバックボーンの変化を検出する場合、および
短時間で判断が必要な場合です。領域ごとにシークエンス用プライマーを設計する必要が
ありません。バーコードによって、複数のプラスミドを 1 回のランにまとめられます。

1 検体から数検体の短い既知領域を確認するだけの場合は、Sanger シークエンスが簡便です。

所要時間、収量、正確性、検体あたりの費用は、条件によって変わります。条件とは、
検体数、DNA の品質、フローセルの状態、ランの設定、ベースコール、解析環境、および
各施設の判定基準です。

## 必要なもの

- Bash 4 以降
- [SeqKit](https://bioinf.shenwei.me/seqkit/)
- [Flye](https://github.com/mikolmogorov/Flye) 2.9 以降
- デマルチプレックス済みの ONT リード（FASTQ または gzip 圧縮された FASTQ）

## 実行

`fastq_pass/barcodeNN/` を含む作業ディレクトリで実行します。

```bash
chmod +x flye.sh
bash ./flye.sh 1 12
```

既定の出力先は `flye_results/` です。ここにバーコードごとに
`assembly.barcodeNN.fasta` が作られます。

設定は環境変数で変更します。項目の一覧は [README.md](README.md) の
Configuration の表にあります。

```bash
THREADS=24 GENOME_SIZE=12k SAMPLE_SIZE=2000 bash ./flye.sh 1 24
```

## 解釈上の注意

- `GENOME_SIZE`・`SAMPLE_SIZE`・`MIN_OVERLAP` は、対象のプラスミドとリード長の
  分布に合わせて指定します。既定値が適さない場合があります。
- Flye がアセンブリを出力したことは、配列の同一性、構造の正しさ、環状であることの
  いずれの証明にもなりません。Flye の作業ディレクトリ、アセンブリグラフ、リードの
  支持、想定される長さ、および既知の配列との一致を確認します。
- 結果に影響する要因は、バーコード間のクロストーク、キメラリード、入力の品質、
  およびリード数の偏りです。
- 乱数シードは固定しています。ただしサンプリングが再現するのは、入力の順序と
  SeqKit の版が同じ場合に限られます。
- 生の FASTQ・POD5・BAM、および検体が特定できるデータは commit しません。
  同梱の `.gitignore` が主要なものを除外します。
